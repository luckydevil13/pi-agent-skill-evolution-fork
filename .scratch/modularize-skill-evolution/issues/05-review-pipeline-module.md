# 05: Модуль «review-pipeline»: прогоны → proposals за одним интерфейсом

**What to build:** Весь путь от завершённого прогона агента до сохранённых proposals собирается в один module: ред-акция и сериализация сообщений, батчинг по reviewInterval, двухступенчатый протокол (селектор релевантных навыков → ревьюер), парсинг строгого JSON без Markdown-ограждений, ретраи при сбое, выбор модели из конфига, таймаут/abort. Вызов модели — единственная точка, инжектируемая в модуль; в тестах вместо живой модели работает фейк-модель (второй adapter делает seam реальным).

**Blocked by:** 02 (каталог навыков и авторский reference для промпта), 04 (сохранение черновиков proposals)

**Status:** done

- [ ] Модуль не имеет runtime-зависимостей от pi/typebox
- [ ] Красная нить в тесте: фейк-модель отвечает по протоколу → из runs рождаются сохранённые proposals с корректными scope/операциями/хэшами
- [ ] Тест «no_change»: ответ без proposals не создаёт файлов и не шумит
- [ ] Тест протокола: ответ с Markdown-ограждениями парсится; ответ без JSON-объекта → ретрай; два неудачных ретрая → ошибка наружу
- [ ] Тест лимитов: proposals обрезаются до maxProposals; project-scope черновики отбрасываются в недоверенном проекте
- [ ] Тест abort: сигнал отмены прерывает ожидание модели и не оставляет хвостов
- [ ] Поведение расширения не изменилось; `npm test` и `npm run typecheck` зелёные
