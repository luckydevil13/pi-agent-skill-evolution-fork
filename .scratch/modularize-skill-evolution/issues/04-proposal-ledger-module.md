# 04: Модуль «proposal-ledger»: жизнь предложения и транзакция

**What to build:** Вся жизнь proposal собирается в один module: модель и валидация операций, дедупликация по содержимому, сохранение с хэшами beforeHash, проверка свежести (файл изменился → stale), транзакционное применение мульти-операции со снапшотами и откатом, ротация устаревших предложений. Интерфейс модуля — единственный способ создать/применить/отклонить предложение; тесты бьют в него напрямую, без pi.

**Blocked by:** 03 (ledger пишет через activity-store: stats/audit/очередь; реестр из 02 нужен для проверки коллизий имён)

**Status:** done

- [ ] Модуль не имеет runtime-зависимостей от pi/typebox
- [ ] Тест транзакции с fault-injection: сбой на середине мульти-операции — уже записанные файлы восстановлены из снапшотов, созданные каталоги удалены, предложение не помечено applied
- [ ] Тест свежести: изменение файла после создания предложения делает apply невозможным и переводит его в stale
- [ ] Тесты валидации операций: create с коллизией имени в scope отклоняется; edit/patch/write без существующего SKILL.md отклоняются; create требует description и непустое тело
- [ ] Тест дедупликации: повторное сохранение идентичного черновика возвращает существующее предложение
- [ ] Тест патч-инварианта внутри транзакции: «find» встречается ровно один раз
- [ ] Поведение расширения не изменилось; `npm test` и `npm run typecheck` зелёные
