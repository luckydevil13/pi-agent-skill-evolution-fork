# 06: Все мутации пакета навыка — через единый транзакционный интерфейс

**What to build:** Прямые файловые записи исчезают из обработчиков: применение proposal, прямой body-патч, disable/enable/purge навыка и удаление legacy-файла статистики идут через один module с интерфейсом вида «план операций / body-патч / смена состояния пакета / purge». Внутри — снапшоты, откат, очередь мутаций, аудит и подсчёт активности как побочный эффект. Инварианты («патч ровно один раз и только в body», свежесть по хэшам, безопасность путей) живут в одном месте и не могут разъехаться между call site.

**Blocked by:** 04 (транзакционная машина ledger'а становится ядром интерфейса)

**Status:** ready-for-agent

- [ ] В коде не осталось write/rename/rm по пакету навыка вне единого интерфейса мутаций (проверяемо grep-ом)
- [ ] disable/enable идут через очередь мутаций и пишут аудит; purge требует подтверждения и удаляет только пакет целиком
- [ ] Прямой body-патч (без proposalId) не может изменить frontmatter и требует явного scope
- [ ] Тесты на временных директориях: каждый путь мутаций (apply, body-патч, disable/enable, purge, legacy-cleanup) оставляет консистентные stats/audit
- [ ] Поведение расширения не изменилось для пользователя; `npm test` и `npm run typecheck` зелёные
