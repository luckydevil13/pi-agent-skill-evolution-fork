# 07: Движок за pi-адаптером: политика отдельно от plumbing (опциональный)

**What to build:** Политика сессии выносится из обработчиков событий pi в движок с узким интерфейсом: инициализация сессии (доверие, конфиг, восстановление курсора), приём завершённого прогона (копление, батчинг, очередь ревью, курсор reviewedThrough), напоминания о неактивных навыках, выполнение операций инструмента и подкоманд с их trust-фильтрами. Обработчики pi остаются тонким маппингом «событие → вызов движка». Тесты гоняют движок на локальном заменителе сессии (временные директории + фейковые session entries) без мока ExtensionAPI.

**Blocked by:** 05 (движок управляет очередью ревью и курсором), 06 (операции инструмента/команд зовут единый интерфейс мутаций)
