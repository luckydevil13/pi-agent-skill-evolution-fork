# 08: Углубление egress: ред-акция по структуре вместо regex-списка (опциональный)

**What to build:** Сериализация прогонов для ревьюера перестраивается с «списка запрещённых regex-паттернов» на «белый список известной структуры сообщений»: наружу уходят только разобранные текстовые поля, изображения и незнакомые формы заменяются заглушками, секреты не могут просочиться через поле, которого нет в списке. Бюджеты усечения сводятся к одному месту. Последней линией защиты перестают быть слова «Never include secrets» в промпте — гарантия обеспечивается кодом и проверяется тестами.


**Status:** ready-for-agent

- [ ] Property-тест на структурированных сообщениях: base64-изображения, токены (sk-, ghp_, xox…), ключи в текстовых полях и незнакомые поля не достигают «промпта» фейк-модели
- [ ] Все бюджетные константы усечения заданы в одном модуле и не дублируются на call site
- [ ] Сериализация не падает на неожиданной структуре сообщения (fallback-заглушка, а не исключение)
- [ ] Скорость/объём: результат сериализации прогона не вырос относительно старой схемы более чем вдвое (ред-акция не раздувает контекст)
- [ ] `npm test` и `npm run typecheck` зелёные; поведение расширения для пользователя не изменилось
