# 03: Модуль «activity-store»: статистика, аудит, очередь записей

**What to build:** Вся персистентность состояния активности собирается в один module: чтение/запись stats (три события: explicitInvocation, skillLoad, management), append-only audit-лог, атомарные записи через очередь файловых мутаций, вычисление неактивных навыков по порогу, удаление legacy-файла статистики при старте сессии. Подсчёт активности перестаёт быть размазанным по call site: обновление статистики и аудит — побочный эффект одного интерфейса, а не ручные вызовы из каждого обработчика.

**Blocked by:** 02 (модуль пользуется путями/реестром из skill-package; правки монофайла последовательны)

**Status:** ready-for-agent

- [ ] Модуль не имеет runtime-зависимостей от pi/typebox
- [ ] Тесты на временных директориях: запись события инкрементирует счётчик и проставляет даты; чтение отсутствующего/битого файла даёт дефолт; версия файла ≠ 2 сбрасывается в дефолт
- [ ] Тест очереди: конкурентные записи в один файл не теряются и не перемешиваются (атомарность через временный файл + rename)
- [ ] Тест миграции: legacy-файл статистики удаляется при старте, новых данных не теряется
- [ ] Тест inactivity: навык без активности и с недавней активностью классифицируются по порогу правильно
- [ ] Поведение расширения не изменилось; `npm test` и `npm run typecheck` зелёные
